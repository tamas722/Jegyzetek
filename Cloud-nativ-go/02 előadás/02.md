# 1. Alapvető adattípusok (Basic Data Types)

A Go nyelv primitív típusai képezik az összetettebb adatszerkezetek építőköveit: logikai értékek, számok és karakterláncok.

## Logikai típus (Boolean) és kommentek

- **Típus:** `bool`, amely 1 bitnyi információt tárol, értéke kizárólag `true` vagy `false` lehet.
- **Műveletek:** A megszokott logikai operátorok támogatottak: ÉS (`&&`), VAGY (`||`), NEGÁCIÓ (`!`). Nincs beépített logikai XOR operátor (helyette a `!=` használható két `bool` között).
- **Kommentek:** Az egysoros komment (`//`) az alapértelmezett stílus, de létezik a C-stílusú többsoros komment (`/* ... */`) is, amit főleg kódrészletek ideiglenes kikommentelésére használnak.

```go
and := true && false // false
or  := true || false // true
not := !true         // false

fmt.Println(and, or, not)

// Ez az alapértelmezett egysoros komment stílus Go-ban
/* Ez pedig egy többsoros komment,
   amivel több sornyi kódot is kizárhatunk a fordításból */
```

## Számtípusok (Numbers)

A Go szigorúan megkülönbözteti a különböző bitméretű és előjeles/előjel nélküli számokat:

| Kategória | Típusok | Magyarázat |
|---|---|---|
| **Előjeles egészek** | `int8`, `int16`, `int32`, `int64` | Negatív és pozitív egész számok tárolására adott bitszélességen. |
| **Előjel nélküli egészek** | `uint8`, `uint16`, `uint32`, `uint64` | Csak nemnegatív ($0$ és pozitív) egész számok tárolására. |
| **Platformfüggő egészek** | `int`, `uint` | Méretük az architektúrától függ (manapság szinte mindig 64 bitesek). Alapértelmezésként mindig `int`-et használunk, ha nincs speciális méretigény. |
| **Lebegőpontos számok** | `float32`, `float64` | IEEE-754 szabvány szerinti törtszámok (alapértelmezett a `float64`). |
| **Típusaliasok** | `byte`, `rune` | A `byte` pontosan megegyezik a `uint8`-cal (nyers bájtokhoz). A `rune` a `uint32` (valójában `int32`) aliasa, és egyetlen Unicode kódpontot (karaktert) jelöl. |
| **Komplex számok** | `complex64`, `complex128` | Két lebegőpontos számból állnak (valós és képzetes rész). A képzetes literál végére közvetlenül egy `i` betűt írunk. |

```go
var x complex64 = -1 + 3.1415i
fmt.Println(x)       // (-1+3.1415i)
fmt.Println(real(x)) // -1 (valós rész kinyerése beépített függvénnyel)
fmt.Println(imag(x)) // 3.1415 (képzetes rész kinyerése)
```

## Karakterláncok (Strings)

- **Működése:** A `string` Unicode kódpontok sorozata, amely a motorháztető alatt egy UTF-8 kódolású bájtokból álló szelet (slice) köré épített csomagoló (wrapper).
- **Megváltoztathatatlanság (Immutability):** A stringek Go-ban **nem módosíthatók** (immutable). Ha egyszer létrejött egy string, a tartalmát memóriában nem írhatod át (minden módosítás új stringet hoz létre).
- **Műveletek:** Mivel bájtok sorozataként viselkedik, a tömbökre és szeletekre vonatkozó műveletek (pl. `len()`, szeletelés `s[1:4]`) stringekre is működnek.

```go
// 1. Idézőjeles literál (double-quote): értelmezi a speciális vezérlőkaraktereket (escape sequences)
s1 := "Hello\nworld!"

// 2. Back-quote literál (raw string): pontosan azt tárolja, amit leírsz, sortörésekkel együtt, escape nélkül
s2 := `Hello
world!`
```

# 2. Változók, konstansok és memóriakezelés (Variables)

## Változók deklarálása (var és :=)

Go-ban a változó típusa (ha kiírjuk) a változó neve **után** áll. Kétféleképpen hozhatunk létre változót:

**`var` kulcsszóval** (csomagszinten és függvényen belül is használható):

- Típussal és kezdőértékkel: `var foo int = 42`
- Típuskikövetkeztetéssel (type inference): `var foo = 42` (a fordító tudja, hogy `int`)
- Több, eltérő típusú változó egyszerre: `var b, f, s = true, 2.3, "four"`
- Kezdőérték nélkül (ekkor zero value-t kap): `var s string`

**Rövid deklarációs operátorral (`:=`)** (kizárólag függvényeken belül használható):

- Egyszerre deklarál és értéket ad automatikus típuskikövetkeztetéssel.
- **Fontos szabály:** Ha egy változót deklarálsz, de később nem használod fel a kódban, az **fordítási idejű hiba!** Ez megakadályozza a felesleges, „ottfelejtett” változók felhalmozódását.
- **Újradeklarálási szabály:** Ha a `:=` bal oldalán új és már létező változók keverednek (ugyanabban a blokkban), akkor a Go létrehozza az új változót, a már létezőnek pedig egyszerűen új értéket ad (ez hibakezelésnél nagyon gyakori).

```go
percent := rand.Float64() * 100.0 // float64 típusú lesz
x, y := 0, 2                      // két int deklarálása egyszerre

result1, err := someFunction1()   // definiálja a result1 és err változókat
result2, err := someFunction2()   // csak a result2 új, az err változót újrahasználja!
```

## Kezdőértékek (Zero Values)

Ha egy változót explicit kezdőérték nélkül deklarálsz, Go-ban soha nem tartalmaz memóriaszemetet, hanem automatikusan megkapja a típusának megfelelő alapértelmezett „nulla értéket” (zero value):

- Egész számok (`int`, stb.): `0`
- Lebegőpontos számok (`float64`, stb.): `0.0`
- Logikai (`bool`): `false`
- Karakterlánc (`string`): `""` (üres string)
- Mutatók (pointerek), szeletek, mapek, interfészek: `nil`

```go
var i int
var f float64
var b bool
var s string

fmt.Printf("integer: %d\n", i) // integer: 0
fmt.Printf("float: %f\n", f)   // float: 0.000000
fmt.Printf("boolean: %t\n", b) // boolean: false
fmt.Printf("string: %q\n", s)  // string: "" (%q idézőjelek közé teszi a stringet)
```

## Az üres azonosító (The Blank Identifier: _)

Mivel a fel nem használt változók fordítási hibát okoznak, a `_` (aláhúzás) segítségével jelezhetjük a fordítónak, hogy egy visszatérési értéket szándékosan figyelmen kívül hagyunk. Emellett használható csomagok mellékhatásért történő importálására is (pl. adatbázis-driverek regisztrálása).

```go
str := "world"
// A fmt.Printf visszaadja a kiírt bájtok számát és egy hibát. Az elsőt eldobjuk:
_, err := fmt.Printf("Hello %s\n", str)
if err != nil {
    // Hibakezelés
}

// Teljesen biztonságosnak tekintett függvényeknél mindkét visszatérési érték elhagyható:
fmt.Printf("Hello world\n")

// Csomag importálása csak az init() mellékhatása miatt:
import _ "github.com/lib/pq"
```

## Konstansok és felsorolások (const és iota)

**Konstans (`const`):** Olyan, mint a változó, de értéke megváltoztathatatlan, fordítási időben ismertnek kell lennie, és kötelező kezdőértéket adni neki (nincs zero value-ja).

**Enumok és az `iota`:** Go-ban nincs külön `enum` kulcsszó. Helyette konstansok csoportosításával és az `iota` azonosítóval készítünk felsorolásokat. Az `iota` minden `const` kulcsszó megjelenésekor 0-ra áll vissza, és a blokkon belül soronként 1-gyel növekszik (a kifejezést nem is kell megismételni a következő sorokban).

```go
const (
    StatusOK          = 200
    StatusBadRequest  = 400
    StatusNotFound    = 404
)

// Enum készítése saját típussal és iota-val:
type Direction int

const (
    North Direction = iota // 0
    East                   // 1 (automatikusan örökli a Direction típust és az iota+1 értéket)
    South                  // 2
    West                   // 3
)

// Saját String() metódus definiálása, hogy szövegesen is ki tudjuk íratni:
func (d Direction) String() string {
    return []string{"North", "East", "South", "West"}[d]
}

var d Direction = West
fmt.Println(int(d))     // 3
fmt.Println(d.String()) // West
```

## Automatikus memóriakezelés (Stack, Heap, Escape Analysis)

Go-ban nincs manuális `malloc`/`free` vagy `delete`.

- A lokális változók alapértelmezés szerint a **veremre (stack)** kerülnek, amelynek élettartama az adott függvényhíváshoz kötött, így a függvény végén villámgyorsan felszabadul.
- **Szökési elemzés (Escape Analysis):** A Go fordító elemzi a változók élettartamát. Ha egy függvény visszaadja egy lokális változó memóriacímét (`return &x`), a fordító észreveszi, hogy `x` túléli a függvényt („elszökik” a scope-ból), ezért automatikusan a **kupacra (heap)** foglalja le, ahol később a Garbage Collector (GC) takarítja el.
- **Buktató (Gotcha):** Attól még, hogy van GC, egy `nil` pointer feloldása (dereferencing) futásidejű összeomlást (`panic` / segfault) okoz!

```go
// Ez teljesen biztonságos Go-ban (ellentétben a C/C++-szal!):
func answer() *int {
    x := 42
    return &x // x a heap-re kerül (escape analysis), így main()-ben is érvényes marad
}

func main() {
    n := answer()
    fmt.Println(*n / 2) // 21

    // BUKTATÓ:
    var p *int // nil a kezdőértéke
    *p = 10    // PANIC! Nil pointer dereference!
}
```

# 3. Konténer típusok és mutatók (Container Types & Pointers)

## Tömbök (Arrays)

- **Fogalom:** Rögzített hosszúságú, azonos típusú elemekből álló sorozat. Go-ban a tömb hossza a **típus része** (a `[3]int` és a `[4]int` két teljesen különböző típus).
- **Kezdőérték:** A megfelelő hosszúságú tömb, feltöltve az elemek zero value-jával.
- **Hossz lekérdezése:** A beépített `len()` függvénnyel.

```go
var a [3]int         // [0 0 0]
a[1] = 42            // [0 42 0]

b := [3]int{2, 4, 6}   // Tömb literál megadott mérettel
c := [...]int{2, 4, 6} // A fordító számolja meg az elemeket ([3]int lesz)
fmt.Println(len(c))    // 3
```

## Szeletek (Slices) – A tömbök dinamikus testvérei

- **Fogalom:** Dinamikusan átméretezhető sorozat (`[]T`), a Go leggyakrabban használt adatszerkezete.
- **Belső felépítése (3 elemű leíró struktúra):** Egy szelet valójában nem maga tárolja az adatokat, hanem egy háttértömbre (backing array) mutató ablak:
  - **Data (Pointer):** Mutató a háttértömb első olyan elemére, amely a szelethez tartozik.
  - **Len (Length):** A szelet aktuális elemszáma (`len(s)`).
  - **Cap (Capacity):** A szelet maximális kapacitása (`cap(s)`), vagyis hogy a kezdőmutatótól számítva hány elem fér el a háttértömbben újrafoglalás nélkül.

```go
// 1. Létrehozás a make() függvénnyel:
n := make([]int, 3) // [0 0 0] -> típusa []int (NEM [3]int!)
n[0], n[1], n[2] = 8, 16, 32

// 2. Létrehozás literállal (elhagyjuk a méretet a szögletes zárójelből):
m := []int{1, 2}

// 3. Bővítés az append() függvénnyel (ha elfogy a kapacitás, új háttértömböt foglal):
m = append(m, 3, 4)    // [1 2 3 4]
m = append(m, m...)    // [1 2 3 4 1 2 3 4] (a ... operátor kicsomagolja a szeletet)

// 4. Szeletelés s[i:j] (i inkluzív /benne van/, j exkluzív /már nincs benne/):
s0 := []int{0, 1, 2, 3, 4, 5, 6}
s1 := s0[1:4]          // [1 2 3]
fmt.Println(s0[:4])    // [0 1 2 3] (az első index alapértelmezetten 0)
fmt.Println(s0[3:])    // [3 4 5 6] (a második index alapértelmezetten len(s0))
```

**Kritikus működés (Megosztott háttértömb):** Mivel az alszeletek ugyanarra a háttértömbre mutatnak, ha módosítasz egy elemet az egyikben, az a többiben is megváltozik!

```go
s0 := [7]int{0, 1, 2, 3, 4, 5, 6}
s1 := s0[1:4] // [1 2 3]
s0[3] = 42
fmt.Println(s1) // [1 2 42] -> s1 is megváltozott!
```

## Asszociatív tömbök (Maps)

- **Fogalom:** Kulcs-érték párokat tároló hasítótábla: `map[K]V`.
- **Kulcsfeltétel:** A kulcs típusának (`K`) **összehasonlíthatónak** kell lennie az `==` operátorral (pl. `string`, `int`, `struct` – de szelet vagy másik map nem lehet kulcs).
- **Nem létező kulcs és a „comma ok” idióma:** Ha egy nem létező kulcsot kérsz le, a map nem dob hibát, hanem visszaadja az értéktípus (`V`) zero value-ját. Hogy megkülönböztessük a „nincs benne” esetet a „benne van, és az értéke 0” esettől, két visszatérési értéket kérünk le.

```go
// Létrehozás make()-kel vagy literállal (többsoros literálnál a záró vessző kötelező!):
freezing := map[string]float32{
    "celsius":    0.0,
    "fahrenheit": 32.0,
    "kelvin":     273.2,
}

delete(freezing, "kelvin") // Elem törlése

// Létezés ellenőrzése ("comma ok" idióma):
newton, ok := freezing["newton"] // newton == 0, ok == false
if !ok {
    fmt.Println("Nincs ilyen kulcs a mapben!")
}

// Ha csak a létezésre vagyunk kíváncsiak:
_, exists := freezing["celsius"] // exists == true
```

## Mutatók (Pointers)

- **Fogalom:** Egy változó memóriacímét tároló típus (`*T`). Minden változónak van memóriacíme (a konstansoknak viszont nincs!).
- **Operátorok:**
  - `&` (address-of): Lekéri egy változó memóriacímét.
  - `*` (dereference): Eléri/módosítja a memóriacímen tárolt értéket.
- **Biztonsági korlát:** Go-ban **tilos a pointer-aritmetika** (pl. `p++` vagy `p + 1` fordítási hiba). A pointerek zero value-ja `nil`, és összehasonlíthatók az `==` operátorral.

```go
var a int = 10
p := &a               // p típusa *int, értéke 'a' memóriacíme
fmt.Printf("%T\n", p) // *int (%T kiírja a változó típusát)

*p = 20               // A mutatott érték módosítása
fmt.Println(a)        // 20
```

# 4. Vezérlési szerkezetek (Control Structures)

## Ciklusok (for és range)

Go-ban kizárólag **egyetlen** ciklusszervező kulcsszó létezik: a `for` (nincs `while` vagy `do-while`). A feltétel körül nincs zárójel, a kapcsos zárójel `{}` viszont kötelező.

```go
// 1. Klasszikus háromrészes for ciklus (i csak a cikluson belül él):
sum := 0
for i := 0; i < 10; i++ {
    sum += i
}

// 2. "While" stílusú ciklus (az inicializáló és léptető rész elhagyásával):
i := 0
for i < 10 {
    i++
}

// 3. Bejárás a 'range' kulcsszóval (tömbök, szeletek, mapek, stringek):
s := []int{2, 4, 8}
for idx, val := range s {
    fmt.Println(idx, "->", val)
}
for _, val := range s { /* csak az érték kell */ }
for idx := range s    { /* csak az index kell */ }

// Map bejárása (FIGYELEM: a mapek bejárási sorrendje Go-ban szándékosan véletlenszerű!):
m := map[int]string{1: "Jan", 2: "Feb"}
for k, v := range m {
    fmt.Println(k, "->", v)
}
```

**Go 1.22+ változás (range ciklusváltozók):** Régebbi Go verziókban a `range` ciklusváltozója (`v`) egyetlen memóriacímen élt és minden iterációban felülíródott (így `&v` mindig ugyanoda mutatott). Go 1.22-től minden iterációban új példány jön létre, így a `&v` használata biztonságos.

## Szeletek és mapek másolása (Buktató!)

**Szelet másolása (`copy`):** A beépített `copy(cel, forras)` függvény csak annyi elemet másol át, amekkora a kisebb szelet hossza. Ha a cél szelet üres (`nil`), 0 elemet másol át! Először `make()`-kel le kell foglalni a megfelelő méretet.

**Map másolása:** Nincs beépített `copy` kulcsszó; `make()`-kel létrehozunk egy új mapet, és egy `for-range` ciklussal átmásoljuk az elemeket.

```go
s := []string{"one", "two", "three"}

// ROSSZ:
var s2 []string
copy(s2, s) // s2 üres marad ([]), mert len(s2) == 0!

// JÓ:
s3 := make([]string, len(s))
copy(s3, s) // [one two three]
```

## Elágazások (if és switch)

**`if` utasítás:** Nincs zárójel a feltétel körül, a `{}` kötelező. Megelőzheti egy rövid inicializáló utasítás, amelynek változója csak az `if-else` blokkon belül látható.

**`switch` utasítás:** Felülről lefelé értékeli ki az ágakat, az első igaz ágnál megáll. **Nincs automatikus továbbcsorgás (fallthrough)**, tehát nem kell `break`-et írni. Ha mégis tovább akarunk lépni a következő ágra, explicit ki kell írni a `fallthrough` kulcsszót. Egy `case`-ben több érték is felsorolható vesszővel, sőt feltétel nélküli (`switch { ... }`) formában tetszőleges logikai kifejezések is vizsgálhatók.

```go
// Inicializáló utasítással egybekötött if:
if err := os.Open("foo.ext"); err != nil {
    panic(err) // Azonnal leállítja a programot nem-nulla hibakóddal
}
// Az 'err' változó itt már nem létezik!

// Switch több értékkel és fallthrough-val:
switch grade {
case "A":
    fmt.Println("Excellent")
case "B", "C":
    fmt.Println("Well done")
    fallthrough // Továbbengedi a vezérlést a "D" ágra is!
case "D":
    fmt.Println("You passed")
default:
    fmt.Println("Invalid grade")
}
```

# 5. Hibakezelés (Error Handling)

Go-ban **nincsenek hagyományos kivételek** (try-catch). A hibák egyszerű értékek, amelyek megvalósítják a beépített `error` interfészt:

```go
type error interface {
    Error() string
}
```

- **Idiomatikus konvenció:** A hibát képes függvények **utolsó visszatérési értékként** egy `error` típust adnak vissza. Ha az értéke `nil`, minden rendben ment; ha nem `nil`, hiba történt.
- A visszaadott hiba eldobása (`_`) súlyos hibának számít Go-ban (a linterek azonnal figyelmeztetnek rá).
- **Új hiba létrehozása:** Egyszerű szöveggel az `errors.New(...)`, formázott szöveggel a `fmt.Errorf(...)` függvénnyel történik. Saját hibatípust bármely `struct`-ból készíthetünk, ha írunk hozzá egy `Error() string` metódust.

```go
func performSomeOperation() error {
    // 1. Külső függvény hívása és azonnali hibaellenőrzés:
    resp, err := http.Get("https://www.example.com")
    if err != nil {
        // Hiba továbbadása a hívónak (akár kontextussal kiegészítve):
        return fmt.Errorf("sikertelen HTTP kérés: %w", err)
    }
    defer resp.Body.Close()

    // 2. Egyszerű hiba generálása:
    if resp.StatusCode != 200 {
        return errors.New("nem 200-as státuszkód érkezett")
    }

    return nil // Minden sikeres volt
}
```

# 6. Egy Go program anatómiája (The Anatomy of a Go Program)

Minden Go forrásfájl felépítése szigorú szabályokat követ:

```go
package main // 1. Csomag deklaráció (mindig az első sor!)

import "fmt" // 2. Külső vagy standard csomagok importálása

// 3. Belépési pont (main csomagban lévő main függvény)
func main() {
    fmt.Println("Hello, world!")
}
```

- **Csomagok (package):** Minden Go program csomagokba (névterekbe) szerveződik. Az azonos könyvtárban lévő, azonos `package <név>` sorral kezdődő fájlok egyetlen csomaggá fordulnak össze.
- **`package main` és `func main()`:** A `main` egy speciális csomagnév, amely azt jelzi a fordítónak, hogy futtatható alkalmazást készítünk (nem pedig könyvtárat). A benne lévő, paraméter és visszatérési érték nélküli `main()` függvény a program belépési pontja.
- **Importálás:** Az `import "fmt"` betölti a standard könyvtár `fmt` csomagját (több mint 100 beépített csomag van, külső csomagokat a `go get` paranccsal telepíthetünk). A csomag elemeit minősített névvel érjük el (`fmt.Println`).

**Pontosvesszők és kötelező kódstílus (gofmt):**

- Go-ban **nem írunk pontosvesszőt** (`;`) a sorok végére (a fordító lexikális elemzője automatikusan beszúrja őket a sortöréseknél).
- Éppen emiatt a kapcsos zárójelek elhelyezése **nem ízlés kérdése, hanem szintaktikai szabály**: a nyitó `{` zárójelnek kötelezően ugyanabban a sorban kell lennie, mint a `func`, `if` vagy `for` fejlécének (ha új sorba teszed, a fordító pontosvesszőt szúr be elé, és fordítási hibát kapsz).
- A `gofmt` eszköz automatikusan a hivatalos Go szabványra formázza a kódot.
