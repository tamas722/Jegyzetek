# 1. Webalkalmazások és a Leaderboard architektúrája (Web Applications)

## A webalkalmazás háromrétegű felépítése

A webalkalmazás olyan program, amely az interneten keresztül, böngészőfelületen érhető el. Három logikai rétegből áll:

- **Prezentációs réteg (Frontend / Presentation tier):** HTML5/CSS alapú megjelenítés és JavaScript klienslogika a böngészőben.
- **Üzleti logikai réteg (Backend / Business logic tier):** Webszerver és alkalmazásszerver, amely megvalósítja az üzleti logikát és kezeli az adattárolást.
- **Adatbázis réteg (Database tier):** A kliensek adatainak perzisztens tárolásáért és lekérdezéséért felelős adatbázis-szerver.

**Kommunikáció:** A kliensek és a szerverek szabványos HTTP vagy WebSocket protokollon keresztül kommunikálnak.

## A mintaalkalmazás: Ranglista (Leaderboard)

Az előadás egy verseny állását megjelenítő Leaderboard webalkalmazáson keresztül mutatja be a Go webes eszköztárát és a felhős telepítést. Az alkalmazást kezdetben monolitikus Go programként építjük fel, amely a következő feladatokat látja el:

- Kiszolgál egy statikus HTML/JS/CSS oldalt, amely megjeleníti a ranglistát és egy űrlapot új pontszámok beküldéséhez.
- Megvalósítja a `getScores` JSON/HTTP API végpontot, amely pontszám szerint csökkenő sorrendben visszaadja a résztvevők listáját.
- Megvalósítja az `addScore` JSON/HTTP API végpontot, amely egy adott nevű játékos (`name`) aktuális pontszámához hozzáadja a beküldött pontokat (`points`).
- Tárolja a felhasználónevekhez tartozó aktuális pontszámokat.

## Fejlesztési és telepítési munkafolyamat (Workflow)

Egy cloud-native Go webalkalmazás elkészítésének lépései:

1. **Modul inicializálása:** Üres Go modul létrehozása a `go mod init` paranccsal.
2. **Fejlesztés és egységtesztelés:** A HTTP szerver kódjának megírása (`src1.go`, `src2.go`) és egységtesztek futtatása (`src_test.go`).
3. **Konténerizáció:** Docker/Podman konténerkép (container image) építése Dockerfile alapján, majd feltöltése egy container registry-be.
4. **Telepítés Kubernetesbe:** Kubernetes manifest fájlok megírása és az alkalmazás telepítése a klaszterbe.

> (Megjegyzés: Valós környezetben ezt kiegészíti a Git verziókezelés, a GitOps – amikor a Kubernetes manifestek is Gitben vannak –, az integrációs tesztelés, valamint az automatizált CI/CD folyamatok.)

# 2. Webes eszköztár Go-ban (net/http és encoding/json)

## HTTP szerver építése a net/http csomaggal

A Go standard könyvtárának `net/http` csomagja külső keretrendszer nélkül is teljes értékű, éles környezetben használható HTTP szervert biztosít.

```go
package main

import "net/http"

// helloGoHandler egy http.HandlerFunc szignatúrájú függvény:
// r (*http.Request) tartalmazza a bejövő kérést,
// w (http.ResponseWriter) segítségével állítjuk össze a választ.
func helloGoHandler(w http.ResponseWriter, r *http.Request) {
	w.Write([]byte("Hello net/http!\n"))
}

func main() {
	// Útvonal-hozzárendelés (routing): a "/" útvonalra érkező kéréseket a handlerhez irányítja
	http.HandleFunc("/", helloGoHandler)

	// Szerver indítása a 8080-as porton (blokkolja a főszálat, csak hiba esetén tér vissza)
	http.ListenAndServe(":8080", nil)
}
```

- **`http.HandlerFunc`:** Olyan függvénytípus, amelynek szignatúrája `func(http.ResponseWriter, *http.Request)`.
- **`http.ResponseWriter`:** Megvalósítja a standard `io.Writer` interfészt, így a `Write([]byte(...))` metódussal írhatjuk bele a válasz törzsét, amelyet a Go automatikusan visszaküld a kliensnek.
- **Tesztelés parancssorból:** A `go run *.go` indítás után a `curl http://localhost:8080` paranccsal ellenőrizhető a szerver válasza.

## JSON kezelés és az encoding/json csomag

A böngészők és webszerverek jellemzően JSON (JavaScript Object Notation) formátumban cserélnek adatot, mert szöveges, emberek számára is könnyen olvasható és hibakereshető, a JavaScript pedig natívan kezeli (nagy teljesítménykritikus mikroszolgáltatások között a gRPC az alternatívája).

- **Struct tagek (Struct tags):** A Go struktúrák mezői mögé backtick (`` `...` ``) jelek közé írt metaadatokkal adhatjuk meg, hogyan képeződjenek le a Go mezők a JSON kulcsokra.
  - Az ismeretlen JSON kulcsokat a Go alapértelmezés szerint figyelmen kívül hagyja.
  - Az `omitempty` opcióval (pl. `` `json:"points,omitempty"` ``) megjelölhetők az opcionális mezők, amelyek üres/zero érték esetén kimaradnak a generált JSON-ból.
- **Szerializálás és deszerializálás (encoding/json):**
  - `json.Marshal(v any) ([]byte, error)`: Go adatszerkezetet alakít JSON formátumú bájtszeletté.
  - `json.Unmarshal(data []byte, v any) error`: JSON bájtszeletet dolgoz fel egy Go struktúrába. **Fontos szabály:** a `v` paramétert inicializálni kell, és mutatóként (`&score`) kell átadni!

```go
// Score egy név-pontszám párost reprezentál.
type Score struct {
	Name   string `json:"name"`   // Go: Name <-> JSON: "name"
	Points int    `json:"points"` // Go: Points <-> JSON: "points"
}

func jsonDemo() {
	// 1. Go struct -> JSON (Marshal)
	s := Score{Name: "user1", Points: 12}
	data, err := json.Marshal(s)
	if err != nil {
		panic(err)
	}
	fmt.Println(string(data)) // {"name":"user1","points":12}

	// 2. JSON -> Go struct (Unmarshal)
	rawJSON := []byte(`{"name": "user1", "points": 12}`)
	var parsed Score
	if err := json.Unmarshal(rawJSON, &parsed); err != nil { // Pointert (&parsed) kell átadni!
		panic(err)
	}
	fmt.Println(parsed) // {user1 12}
}
```

# 3. Az adatréteg megvalósítása (The Data Layer)

## Absztrakció interfésszel (DataLayer)

Az adatréteget egy interfész mögé rejtjük, így később az üzleti logika és a HTTP szerver módosítása nélkül cserélhetjük le a memóriabeli tárolót egy valódi adatbázisra.

```go
// DataLayer absztrahálja a ranglista adattárolási műveleteit.
type DataLayer interface {
	Add(score Score) error    // Megadott felhasználó pontszámának növelése
	List() ([]Score, error) // Tárolt pontszámok lekérdezése tetszőleges sorrendben
}
```

> (Megjegyzés a diákkal kapcsolatban: a 15. dián a `Score` struktúrában elírásként `Score int` és `json:"score"` szerepel, de az összes többi kódrészletben és JSON példában `Points int` és `json:"points"` van használva.)

## Memóriabeli, szálbiztos tároló (localDB)

**Párhuzamosság biztonsága (`sync.RWMutex`):** A Go HTTP szervere minden bejövő kérést külön goroutine-ban szolgál ki, ezért az adatréteget több szál érheti el egyszerre. A belső `[]Score` szeletet egy olvasó-író zárral (`sync.RWMutex`) védjük.

**Go tervezési minta (Konstruktor interfész visszatérési értékkel):** A `NewDataLayer()` konstruktor a konkrét `&localDB` struktúrát `DataLayer` interfészként adja vissza, így elrejti a belső implementációs részleteket.

**Buktató a `List()` metódusban (Másolat visszaadása):** A `List()` nem adhatja vissza közvetlenül a `db.scores` szeletet, mert a hívó fél a záron (lock) kívül fogja rendezni az eredményt – ez versenyhelyzetet (data race) okozna, és átrendezné a belső tárolót is. Ezért olvasási zár (`RLock`) mellett készítünk egy azonos méretű másolatot (`make` + `copy`), és azt adjuk vissza.

```go
type localDB struct {
	scores []Score
	mu     sync.RWMutex
}

// NewDataLayer létrehoz egy új memóriabeli adatbázist interfészként visszaadva.
func NewDataLayer() DataLayer {
	return &localDB{scores: []Score{}}
}

// Add növeli a játékos pontszámát, vagy felveszi új játékosként.
func (db *localDB) Add(score Score) error {
	db.mu.Lock()         // Kizárólagos írási zár
	defer db.mu.Unlock() // Garantált feloldás visszatéréskor

	for i := range db.scores {
		if db.scores[i].Name == score.Name {
			db.scores[i].Points += score.Points
			return nil
		}
	}
	db.scores = append(db.scores, score)
	return nil
}

// List visszaadja a ranglista másolatát.
func (db *localDB) List() ([]Score, error) {
	db.mu.RLock()         // Megosztott olvasási zár
	defer db.mu.RUnlock() // Garantált feloldás visszatéréskor

	ret := make([]Score, len(db.scores))
	copy(ret, db.scores)
	return ret, nil
}
```

## Egységteszt írása az adatréteghez

A tesztfájl (`*_test.go`) a `NewDataLayer()`, `Add()` és `List()` működését ellenőrzi, és a `go test ./...` paranccsal futtatható.

```go
func TestDataLayerLocal(t *testing.T) {
	db := NewDataLayer()
	db.Add(Score{"a", 12})

	scores, _ := db.List()
	if len(scores) != 1 {
		t.Errorf("add: expected 1 score, got %d", len(scores))
	}
	if scores[0].Name != "a" {
		t.Errorf("add: expected name %q, got %q", "a", scores[0].Name)
	}
	if scores[0].Points != 12 {
		t.Errorf("add: expected score 12, got %d", scores[0].Points)
	}
}
```

# 4. A teljes HTTP szerver felépítése (HTTP Server)

A szerver inicializálása a `go mod init leaderboard` paranccsal történik. Az API végpontok és a statikus HTML kiszolgálásának teljes működése:

- **`handleAddScore` (`/api/addScore`):**
  - A `json.NewDecoder(r.Body).Decode(&score)` segítségével közvetlenül a HTTP kérés adatfolyamából (stream) olvassa ki a JSON-t.
  - Hibás JSON formátum esetén `http.Error(w, err.Error(), http.StatusBadRequest)` (HTTP 400) választ küld és visszatér.
  - Sikeres feldolgozásnál naplózza a kérést (`log.Printf`), meghívja a `db.Add(score)` metódust, és `http.StatusOK` (HTTP 200) státuszkódot küld.
- **`handleGetScores` (`/api/getScores`):**
  - Lekéri a pontszámokat a `db.List()` hívással.
  - A `sort.Slice` függvénnyel és egy névtelen összehasonlító függvénnyel csökkenő sorrendbe rendezi a listát pontszám szerint.
  - A `json.Marshal(scores)` segítségével JSON-ná alakítja (hiba esetén HTTP 500 `StatusInternalServerError` választ ad).
  - Beállítja a `Content-Type: application/json` fejlécet, majd kiírja a választ.
- **`main()` és naplózás (`log`):**
  - A `log.SetFlags(log.LstdFlags | log.Lshortfile)` beállítja, hogy minden naplóbejegyzés tartalmazza a dátumot, pontos időt, valamint a forrásfájl nevét és sorának számát.
  - A gyökérútvonalon (`/`) a `http.ServeFile(w, r, "static/index.html")` szolgálja ki a frontendet.
  - A `log.Fatal(http.ListenAndServe(":8080", nil))` elindítja a szervert, és hiba esetén naplózza a hibát, majd leállítja a programot.

```go
package main

import (
	"encoding/json"
	"log"
	"net/http"
	"sort"
)

var db DataLayer

func handleAddScore(w http.ResponseWriter, r *http.Request) {
	var score Score
	err := json.NewDecoder(r.Body).Decode(&score)
	if err != nil {
		http.Error(w, err.Error(), http.StatusBadRequest)
		return
	}

	log.Printf("Handling addScore request: name=%s, points=%d", score.Name, score.Points)
	db.Add(score)
	w.WriteHeader(http.StatusOK)
}

func handleGetScores(w http.ResponseWriter, r *http.Request) {
	log.Println("Handling getScores request")
	scores, _ := db.List()

	// Rendezés pontszám szerint csökkenő sorrendbe:
	sort.Slice(scores, func(i, j int) bool {
		return scores[i].Points > scores[j].Points
	})

	list, err := json.Marshal(scores)
	if err != nil {
		http.Error(w, err.Error(), http.StatusInternalServerError)
		return
	}

	w.Header().Set("Content-Type", "application/json")
	w.Write(list)
}

func main() {
	log.SetFlags(log.LstdFlags | log.Lshortfile)
	db = NewDataLayer()

	http.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) {
		http.ServeFile(w, r, "static/index.html")
	})
	http.HandleFunc("/api/getScores", handleGetScores)
	http.HandleFunc("/api/addScore", handleAddScore)

	log.Println("Starting HTTP server at :8080")
	log.Fatal(http.ListenAndServe(":8080", nil))
}
```

# 5. Konténerizáció és telepítés Kubernetesbe (Deploying to Kubernetes)

## Linux konténerek és a Go előnye

**Mi az a konténer?** Pehelysúlyú, operációs rendszer szintű virtualizációs absztrakció, amely elszigeteli a folyamatokat a gazdagéptől és egymástól. A virtuális gépekkel (VM) ellentétben megosztja a gazdagép kernelét, így a konténerképek nagyságrendekkel kisebbek.

**Miért ideális a Go?** A Go egyetlen, statikusan linkelt binárisba fordul, amely minden függőséget tartalmaz, így nincs szükség külső futtatókörnyezetre vagy rendszerkönyvtárakra a konténerben.

## Konténerkép építése (Egylépcsős vs. Többlépcsős build)

### 1. Egylépcsős build (Single-stage)

Először helyben lefordítjuk a statikus Linux binárist, majd bemásoljuk egy teljesen üres (`FROM scratch`) alapimage-be:

- `CGO_ENABLED=0`: Kikapcsolja a C könyvtárakhoz való dinamikus linkelést (tisztán statikus bináris készül).
- `GOOS=linux`: Keresztfordítás (cross-compilation) Linux operációs rendszerre.
- `-a`: Minden függő csomag kényszerített újrafordítása.
- `FROM scratch`: A Docker/Podman üres (0 bájtos) alapimage-e, amelyben még egy shell sem található – csak a lefordított Go bináris és a statikus HTML fájlok kerülnek bele, így a végső konténer mérete mindössze ~7 MB!

```bash
# 1. Fordítás:
CGO_ENABLED=0 GOOS=linux go build -a -o leaderboard

# 2. Image építése és feltöltése Podman (vagy Docker) segítségével:
sudo podman build -t localhost/leaderboard -f deploy/Dockerfile .
sudo podman push localhost/leaderboard
```

```dockerfile
# Egylépcsős Dockerfile
FROM scratch
COPY leaderboard /
COPY static/ static/
CMD ["/leaderboard"]
```

### 2. Többlépcsős build (Multi-stage build – Ajánlott!)

Nem szükséges, hogy a helyi gépen telepítve legyen a Go fordító: az első szakaszban egy hivatalos `golang` konténerben lefordítjuk a kódot, a második szakaszban pedig csak a kész binárist másoljuk át a `scratch` image-be.

```dockerfile
# 1. szakasz: Fordítás konténerizált Go környezetben
FROM docker.io/golang:latest as build
COPY . /src
WORKDIR /src
RUN CGO_ENABLED=0 GOOS=linux go build -a -o leaderboard

# 2. szakasz: A végső, minimális méretű futtató konténer felépítése
FROM scratch
COPY --from=build /src/leaderboard /
COPY static/ static/
CMD ["/leaderboard"]
```

## Telepítés Kubernetesbe (kubectl)

A kész konténerképet két paranccsal elindíthatjuk és publikussá tehetjük a Kubernetes klaszterben:

```bash
# 1. Deployment létrehozása (Minikube esetén a kép neve: localhost/leaderboard):
kubectl create deployment leaderboard --image=leaderboard

# 2. Külső elérés biztosítása LoadBalancer típusú Service-szel:
kubectl expose deployment leaderboard --type=LoadBalancer --port 8080

# 3. Külső IP-cím ellenőrzése:
kubectl get service leaderboard
```

> **Minikube megjegyzés:** Ha az `EXTERNAL-IP` egy percnél tovább `<pending>` állapotban marad, nincs futó load balancer – Minikube alatt külön terminálban el kell indítani a `minikube tunnel &` parancsot.

## A klaszterben futó szolgáltatás tesztelése

A `kubectl` JSONPath lekérdezésével környezeti változóba menthetjük a kiosztott külső IP-címet, és ugyanúgy megszólíthatjuk a `curl` vagy böngésző segítségével, mint korábban helyben:

```bash
export EXTERNAL_IP=$(kubectl get service leaderboard -o jsonpath="{.status.loadBalancer.ingress[0].ip}")

curl -H "Content-Type: application/json" --request POST --data \
  '{"name":"a","points":14}' http://${EXTERNAL_IP}:8080/api/addScore

curl http://${EXTERNAL_IP}:8080/api/getScores
```
