# 1. Modulok és csomagok (Modules and Packages)

## Csomagok (package) alapfogalmai

A függvény után a csomag (package) az újrafelhasználhatóság második alapegysége Go-ban: egymáshoz kapcsolódó Go forrásfájlok gyűjteménye egyetlen moduláris, karbantartható egységbe szervezve.

- **Könyvtáralapú szervezés:** Egy Go csomag fizikailag nem más, mint egy könyvtár, amely egy vagy több `.go` forrásfájlt tartalmaz.
- **Deklaráció:** Az adott könyvtárban lévő összes forrásfájl első sorának azonosnak kell lennie: `package <csomagnév>`. Az ezután definiált összes függvény, típus, konstans és változó a csomag részévé válik.
- **Előnyök:** Csökkenti a névütközéseket (minden külső hivatkozás elé ki kell írni a csomag nevét, pl. `fmt.Println`), és gyorsítja a fordítást (ha csak a hívó kód változik, az importált csomagot nem kell újrafordítani).
- **A main csomag:** Speciális csomagnév, amely azt jelzi a fordítónak, hogy futtatható programot (binárist), nem pedig könyvtárat készítünk.

```text
example.com/mymodule/        <-- Modul gyökérkönyvtára
├── LICENSE
├── go.mod                   <-- Modul metaadatai és függőségei
├── go.sum                   <-- Függőségek kriptográfiai ellenőrzőösszegei
├── package1/                <-- Első alcsomag
│   ├── func1.go             (első sor: package package1)
│   └── func2.go             (első sor: package package1)
└── package2/                <-- Második alcsomag
    ├── func1.go             (első sor: package package2)
    └── func2.go             (első sor: package package2)
```

## Modulok (module) és importálás

A Go modul egymással összefüggő Go csomagok gyűjteménye, amely saját azonosítóval, függőségi listával és verziókezeléssel rendelkezik (a publikus Go modulok központi gyűjtőhelye a `pkg.go.dev`).

- **Leíró fájl (`go.mod`):** A modul gyökérkönyvtárában található fájl rögzíti a modul nevét, a Go verziót és a külső függőségeket.
- **Modulazonosító:** Lehet egyszavas név (helyi teszteléshez), de publikáláshoz teljes útvonal alakú azonosítót használunk (`<URL/felhasználónév/név>`, pl. `github.com/my-user/greetings`).
- **Importálás:** Az `import "<modul/csomag>"` utasítással történik. Egy modulon belüli alcsomagot a teljes útvonalával importálunk (pl. `import "github.com/my-user/greetings/pkg/my-package"`).
- **Keresési útvonal felülírása (`replace`):** Alapértelmezés szerint a Go az interneten keresi a modulokat, de a `go.mod` fájl `replace` direktívájával átirányíthatjuk egy helyi fájlrendszerbeli könyvtárra.
- **Terminológiai megjegyzés:** A gyakorlatban a „modul” és a „csomag” kifejezéseket gyakran szinonimaként használják az egyszerűség kedvéért.

## Nevek exportálása (Láthatósági szabályok)

Go-ban nincsenek `public`, `private` vagy `protected` kulcsszavak; a láthatóságot kizárólag az azonosító kezdőbetűje határozza meg:

- **Nagybetűvel kezdődő név:** Exportált (publikus) – más csomagokból is elérhető a `<csomagnév>.<Név>` formában.
- **Kisbetűvel kezdődő név:** Nem exportált (privát) – kizárólag az adott csomagon belüli fájlokból látható.

```go
package mymodule

const MyConst = 12             // Exportált -> kívülről: mymodule.MyConst
var myVar string = "somevalue" // Nem exportált -> csak a mymodule csomagon belül látható

type MyInterface interface{}   // Exportált
type myStruct struct{}         // Nem exportált

func MyFunction() {}           // Exportált -> kívülről: mymodule.MyFunction()
```

## Saját modul létrehozása, tesztelése és dokumentálása (Lépésről lépésre)

**Modul inicializálása:**

```bash
mkdir greetings && cd greetings
go mod init greetings   # Létrehozza a go.mod fájlt (publikáláshoz: github.com/user/greetings)
```

Külső függőségek hozzáadásához a `go get <modul/csomag>`, a `go.mod` fájl karbantartásához és tisztításához pedig a `go mod tidy` parancsot használjuk (a standard könyvtár csomagjait, mint az `fmt` vagy `sync`, nem kell külön hozzáadni).

**A csomag megírása (`greetings.go`):**
A csomagon belül a saját szimbólumokra csomagnév-előtag nélkül hivatkozunk (pl. `Greeting` a `greetings.Greeting` helyett).

```go
// A package to generate heartwarming welcome messages.
package greetings

import "fmt"

// formatString is used to format the greeting message (nem exportált).
const formatString = "%s, %s!"

// Greeting is a short word used to greet people (exportált).
var Greeting string = "Hello"

// Hello returns a greeting for the named person (exportált).
func Hello(name string) string {
	message := fmt.Sprintf(formatString, Greeting, name)
	return message
}
```

**Egységtesztek írása (`greetings_test.go`):**
A tesztek futtatása a `go test *.go -v` paranccsal történik.

```go
package greetings

import "testing"

func TestHelloDefault(t *testing.T) {
	g := Hello("myname")
	if g != "Hello, myname!" {
		t.Errorf("hello-myname: expected %q, got %s", "Hello, myname!", g)
	}
}

func TestHelloCustom(t *testing.T) {
	Greeting = "Hi"
	g := Hello("myname")
	if g != "Hi, myname!" {
		t.Errorf("hello-myname: expected %q, got %s", "Hi, myname!", g)
	}
}
```

**HTML dokumentáció megtekintése (godoc):**
A `godoc -http=:6060` paranccsal helyi dokumentációs szervert indíthatunk, amely a `http://localhost:6060/pkg/greetings` címen rendereli a Godoc kommentekből generált dokumentációt (a publikált csomagoké pedig a `pkg.go.dev` oldalon érhető el).

## Helyi csomag importálása egy másik modulból (go mod replace)

Ha létrehozunk egy különálló `helloworld` modult (`mkdir helloworld && cd helloworld && go mod init helloworld`), amely használni szeretné a még nem publikált `greetings` csomagunkat, a `go get greetings` és a `go run helloworld.go` alapértelmezés szerint hibát dob (`no required module provides package greetings`), mert a Go az interneten keresi a csomagot.

> **Import-csoportosítási szabály:** Az import blokkon belül a standard könyvtári csomagokat és a saját/külső csomagokat üres sorral kell elválasztani (ezt sok Go linter szigorúan ellenőrzi).

**Átirányítás helyi könyvtárra:** A `go mod edit -replace` paranccsal módosítjuk a keresési útvonalat, majd frissítjük a metaadatokat:

```bash
go mod edit -replace greetings=../greetings
go mod tidy
```

Ez bekerül a `helloworld/go.mod` fájlba (`replace greetings => ../greetings`), ezután a `go run helloworld.go` sikeresen lefut.

```go
// helloworld/helloworld.go
package main

import (
	"fmt"

	"greetings" // Üres sor választja el a standard könyvtártól!
)

func main() {
	message := greetings.Hello("Dolly")
	fmt.Println(message) // Hello, Dolly!
}
```

# 2. Párhuzamosság: Goroutine-ok és Csatornák (Concurrency)

## Goroutine-ok

A goroutine egy pehelysúlyú végrehajtási szál, amelyet maga a programba fordított Go futtatókörnyezet (Go runtime) ütemez és menedzsel. Létrehozásuk és futtatásuk töredékébe kerül a hagyományos operációs rendszerbeli szálaknak.

- **Indítás:** Bármely függvényhívás elé írt `go` kulcsszó ütemezi a függvény háttérben történő futtatását, miközben a hívó szál azonnal, megállás nélkül halad tovább.
- **Fontos szabály:** Ha a főszál (`main` függvény) befejeződik, a teljes program azonnal leáll, és minden még futó vagy ütemezett háttér-goroutine megsemmisül anélkül, hogy lefutna.

```go
func hello(arg string) {
	fmt.Println("Hello", arg)
}

func main() {
	go hello("world")             // Háttérben induló goroutine ütemezése
	time.Sleep(1 * time.Second)   // Várakozás, hogy a runtime lefuttassa a goroutine-t
}
```

## A két párhuzamossági modell

Ha több goroutine osztozik egy változón (például egy névtelen függvény / closure referencia szerint elfogja a külső változót), a szinkronizálatlan egyidejű írás-olvasás versenyhelyzethez (data race) és összeomláshoz (panic) vezethet. A Go két modellt támogat:

- **CSP (Communicating Sequential Processes):** Szinkronizáció üzenetküldéssel, csatornákon (channel) keresztül – ez az elsődleges, ajánlott módszer.
- **Klasszikus zárolás:** Kölcsönös kizárás lockokkal és mutexekkel a `sync` csomagból – csak egyszerű, triviális esetekre.

> **Go közmondás (Go Proverb):** „Do not communicate by sharing memory. Instead, share memory by communicating.” (Ne memóriamegosztással kommunikálj, hanem kommunikációval ossz meg memóriát!)

## Csatornák (chan) és blokkolási szabályok

A csatorna (`chan T`) egy típusos csővezeték (typed pipe), amelyen keresztül két goroutine biztonságosan küldhet egymásnak `T` típusú értékeket, miközben szinkronizálják a futásukat.

```go
ch := make(chan int) // Típusos csatorna létrehozása
ch <- 42             // Küldés (send) a csatornába (a nyíl az adat áramlási irányát mutatja)
val := <-ch          // Fogadás (receive) a csatornából új változóba
<-ch                 // Fogadás és az érték eldobása
```

**Pufferolatlan csatorna (`make(chan T)`):** Alapértelmezés szerint minden csatorna pufferolatlan. A küldő goroutine blokkolódik, amíg egy másik goroutine nem fogadja az adatot; a fogadó pedig blokkolódik, amíg valaki nem küld rá. Ez garantálja a determinisztikus szinkronizációt (pl. „ping” -> „pong”):

```go
ch := make(chan string)
defer close(ch)

go func() {
	message := <-ch      // Blokkolva vár a "ping"-re
	fmt.Println(message) // 1. Kiírja: ping
	ch <- "pong"         // Visszaküldi a "pong"-ot
}()

ch <- "ping"             // Elküldi a "ping"-et
fmt.Println(<-ch)        // 2. Blokkolva vár a válaszra, majd kiírja: pong
```

**Pufferelt csatorna (`make(chan T, kapacitás)`):** Belső, rögzített méretű sorral rendelkezik. A küldés csak akkor blokkol, ha a puffer megtelt, a fogadás pedig csak akkor blokkol, ha a puffer üres.

```go
ch := make(chan string, 2) // 2 elemű puffer
ch <- "foo"                // Nem blokkol
ch <- "bar"                // Nem blokkol
// ch <- "baz"             // Ez már BLOKKOLNA, mert tele a puffer!

fmt.Println(<-ch)          // "foo" (nem blokkol)
fmt.Println(<-ch)          // "bar" (nem blokkol)
// fmt.Println(<-ch)       // Ez már BLOKKOLNA, mert üres a puffer!
```

## Csatornák lezárása (close) és bejárása (range)

**Lezárás (`close(ch)`):** A használaton kívüli csatornákat a beépített `close()` függvénnyel zárjuk le.

**Szabályok és veszélyek:**

- Lezárt csatornába történő küldés azonnali futásidejű panic-et okoz!
- Lezárt csatornából történő olvasás először kiüríti a pufferben maradt elemeket, utána pedig azonnal, blokkolás nélkül visszaadja az elemtípus zero value-ját.
- **Ki zárja le?** Kizárólag a küldő fél zárhatja le a csatornát (ha a fogadó zárná le, a küldő pánikba esne a következő küldésnél). Érdemes közvetlenül létrehozás után `defer close(ch)`-t használni.

**Állapotellenőrzés („comma ok”):** A második logikai visszatérési érték (`ok`) megmutatja, hogy él-e még a csatorna (vagy van-e még pufferelt adat): `msg, ok := <-ch` (`ok == false`, ha lezárt és üres).

**Bejárás range ciklussal:** A `for s := range ch` ciklus addig olvassa a csatornát, amíg azt le nem zárják. **Buktató:** Ha a küldő elfelejti lezárni a csatornát, a range ciklus örökre beragad (deadlock)!

```go
ch := make(chan string, 3)
ch <- "foo"
ch <- "bar"
ch <- "baz"
close(ch) // Kötelező lezárni a range előtt!

for s := range ch {
	fmt.Println(s) // Kiírja mindhármat, majd a ciklus tisztán kilép
}
```

# 3. Multiplexálás, Időtúllépés és Megszakítás (select és context)

## A select utasítás

A `select` több csatornaművelet (küldés és fogadás) egyidejű figyelésére szolgál.

- **Működése:** Ha egyszerre több `case` ág is kész a végrehajtásra, a Go **véletlenszerűen** választ egyet közülük.
- **Nem blokkoló működés:** Ha van `default` ág, és egyik csatorna sem áll készen, azonnal a `default` fut le; ha nincs `default`, a `select` blokkolva vár, amíg valamelyik ág teljesül.
- **Buktató (GOTCHA):** Egy lezárt csatorna soha nem blokkol, és mindig olvasható (azonnal visszaadja a zero value-t), ezért a `select` mindig késznek tekinti!

```go
select {
case <-ch1:
	fmt.Println("Érkezett valami (érték eldobva)")
case x := <-ch2:
	fmt.Println("Beolvasva:", x)
case ch3 <- y:
	fmt.Println("Elküldve:", y)
default:
	fmt.Println("Egyik csatorna sem állt készen")
}
```

## Időtúllépés (time.After) és manuális leállítás (cancel csatorna)

**Timeout:** A `time.After(d)` függvény egy olyan csatornát ad vissza, amely `d` idő elteltével küld egy időbélyeget – ezt `select`-be téve könnyen időkorlátot szabhatunk egy csatornaolvasásnak.

**Goroutine leállítása (`<-chan any`):** Mivel kívülről nem lehet „kilőni” egy goroutine-t, egy dedikált, csak olvasható (`<-chan any`) cancel csatornát adunk át neki, amelyre üres struktúrát (`struct{}{}`) küldve jelezzük a leállási szándékot.

```go
// A <-chan any típus garantálja, hogy a függvény csak olvasni tud a csatornából:
func cancellable(cancel <-chan any) {
	select {
	case <-cancel:
		fmt.Println("Cancelled")
	case <-time.After(10 * time.Second):
		fmt.Println("Finished")
	}
}

func main() {
	cancel := make(chan any)
	go cancellable(cancel)
	time.Sleep(5 * time.Second)
	cancel <- struct{}{} // Leállítási jelzés küldése
}
```

## A context csomag

Több egymásba ágyazott goroutine-réteg esetén a kézi cancel csatornák kezelése nehézkes, ezért a standard könyvtár `context` csomagja automatizálja a goroutine-ok élettartamának, leállításának és időkorlátainak kezelését.

- `context.Background()`: Üres gyökérkontextus létrehozása.
- `context.WithCancel(parent)`: Leállítható gyermekkontextust és egy `cancel()` függvényt ad vissza (a `cancel()` meghívása lezárja a `ctx.Done()` csatornát, de a szülő kontextust érintetlenül hagyja).
- `context.WithTimeout(parent, duration)`: Olyan gyermekkontextust hoz létre, amely a megadott idő után automatikusan leáll.

> **Best practice:** A `cancel()` függvényt mindig ütemezzük be `defer cancel()`-lel a hívás után, hogy ne szivárogjanak az erőforrások! A Go standard könyvtár legtöbb hálózati/I/O függvényének van Context-et fogadó változata (pl. `net.Dial` helyett `d.DialContext(ctx, ...)` vagy a rövidített `net.DialTimeout`).

```go
func cancellable(ctx context.Context) {
	select {
	case <-ctx.Done(): // A csatorna lezáródik, ha cancel() fut le vagy lejár a timeout
		fmt.Println("Cancelled")
	case <-time.After(10 * time.Second):
		fmt.Println("Finished")
	}
}

func dialWithTimeout() error {
	var d net.Dialer
	// 1 perces időkorlát (szemben az OS alapértelmezett ~3 perces TCP timeoutjával):
	ctx, cancel := context.WithTimeout(context.Background(), time.Minute)
	defer cancel() // Kötelező meghívni az erőforrások felszabadításához!

	conn, err := d.DialContext(ctx, "tcp", "192.0.2.1:80")
	if err != nil {
		return err
	}
	defer conn.Close()
	_, err = conn.Write([]byte("Hello, World!"))
	return err
}
```

# 4. Megosztott állapot védelme és Tipikus buktatók

## Szálbiztos map készítése (sync.RWMutex)

Go-ban a beépített `map` **nem szálbiztos**: ha az egyik goroutine írja, miközben egy másik olvassa, a program futásidejű hibával összeomlik.

**Megoldás (`sync.RWMutex`):** Olvasó-író zár, amely egyszerre több párhuzamos olvasót enged be (`RLock` / `RUnlock`), de íráshoz kizárólagos hozzáférést biztosít (`Lock` / `Unlock`), ilyenkor sem más író, sem olvasó nem léphet be.

**Konstruktor minta (`NewXXX`):** Go-ban nincsenek osztálykonstruktorok; az idiomatikus megoldás egy `NewConcurrentMap()` függvény, amely a privát (kisbetűs) `concMap` struktúra példányát egy publikus `ConcurrentMap` interfész mögé rejtve adja vissza, így kívülről senki sem tudja megkerülni a zárolást.

```go
type ConcurrentMap interface {
	Set(key, value int)
	Get(key int) (value int, ok bool)
}

type concMap struct {
	store map[int]int
	lock  sync.RWMutex
}

func (m *concMap) Set(key, value int) {
	m.lock.Lock()         // Kizárólagos írási zár
	defer m.lock.Unlock() // Garantált feloldás visszatéréskor
	m.store[key] = value
}

func (m *concMap) Get(key int) (value int, ok bool) {
	m.lock.RLock()         // Megosztott olvasási zár
	defer m.lock.RUnlock() // Garantált feloldás visszatéréskor
	value, ok = m.store[key]
	return
}

func NewConcurrentMap() ConcurrentMap {
	return &concMap{
		store: make(map[int]int),
	}
}
```

> (Megjegyzés: Az előadás diáján a metódusok érték-fogadóval szerepelnek, de a gyakorlatban pointer-fogadó `*concMap` szükséges, hogy a `sync.RWMutex` ne másolódjon le minden híváskor.)

## Kritikus buktató: Ciklusváltozók elfogása lezárásokban (Closures in Goroutines)

Az alábbi kód tipikus csapdát mutat be, amikor ciklusban indítunk goroutine-okat:

```go
for num := range []int{1, 2, 3, 4, 5} {
	go func() {
		fmt.Println(num)
	}()
}
time.Sleep(time.Second)
```

**Miért írt ki régebben öt darab 5-öst (5 5 5 5 5)?** A Go 1.22 előtti verziókban a `num` ciklusváltozó egyetlen memóriacímen élt, és a lezárás (closure) referencia szerint fogta el. Mire a goroutine-ok ténylegesen elindultak, a ciklus már végigfutott, és `num` értéke 5 lett.

**Mi változott Go 1.22-től?** A Go 1.22-es verziótól kezdve a nyelv minden iterációban automatikusan új példányt hoz létre a ciklusváltozóból, így a kód kiírja az 1–5 számokat – azonban az ütemezés miatt teljesen véletlenszerű sorrendben.

**`go vet` statikus elemző:** Mindig építsd be a `go vet` parancsot a fejlesztési folyamatba, mert figyelmeztet a gyanús konstrukciókra (például: `loop variable num captured by func literal`), amelyeket a fordító egyébként engedne.

**A két klasszikus javítási minta (régebbi Go verziókhoz és az egyértelműség kedvéért):**

```go
// 1. megoldás: Ciklusváltozó árnyékolása (lokalizálása) az iteráción belül
for num := range []int{1, 2, 3, 4, 5} {
	num := num // Saját lokális példány minden goroutine-nak
	go func() { fmt.Println(num) }()
}

// 2. megoldás: Átadás függvényparaméterként (érték szerint másolódik)
for num := range []int{1, 2, 3, 4, 5} {
	go func(i int) { fmt.Println(i) }(num)
}
```
