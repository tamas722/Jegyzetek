# 1. Függvények (Functions)

A függvény egy újrafelhasználható kódblokk, amely egy programrészlet viselkedését foglalja egységbe.

## Alapszintaxis, visszatérési értékek és rekurzió

- **Deklaráció:** A `func` kulcsszóval kezdődik, ezt követi a függvény neve, a paraméterlista (Go-ban a típus itt is a paraméter neve után áll), az opcionális visszatérési típus(ok), majd a kapcsos zárójelek közötti függvénytörzs.
- **Egyszerűsített paraméterlista:** Egymást követő, azonos típusú paramétereknél elég csak az utolsó után kiírni a típust (pl. `x, y int`).
- **Nevesített visszatérési változók (Named return variables):** A visszatérési értékeknek nevet is adhatunk a fejlécben; ekkor lokális változóként viselkednek, és egy üres `return` utasítás (naked return) visszaadja az aktuális értéküket (főleg rövid függvényekben ajánlott).
- **Több visszatérési érték:** Go-ban egy függvény tetszőleges számú értéket visszaadhat (ez az alapja a `(eredmény, error)` konvenciónak is).
- **Rekurzió:** A Go támogatja a gyakorlatilag korlátlan mélységű rekurzív függvényhívásokat (dinamikusan növekvő goroutine stack miatt).

```go
// Egyszerűsített paraméterlista (mindkettő int):
func add(x, y int) int {
	return x + y
}

// Nevesített visszatérési változó és üres return:
func addNamed(x, y int) (z int) {
	z = x + y
	return
}

// Több visszatérési érték:
func swap(x, y string) (string, string) {
	return y, x
}

// Rekurzív függvény:
func factorial(n int) int {
	if n < 1 {
		return 1
	}
	return n * factorial(n-1)
}

func main() {
	a, b := swap("foo", "bar")
	fmt.Println(a, b)          // bar foo
	fmt.Println(factorial(11)) // 39916800
}
```

## A defer kulcsszó (Halasztott végrehajtás)

- **Működése:** A `defer` kulcsszóval megjelölt függvényhívás végrehajtását a Go elhalasztja egészen addig, amíg az őt körülvevő függvény közvetlenül a visszatérés előtt nem áll.
- **Végrehajtási sorrend (LIFO):** Ha egy függvényben több `defer` utasítás is szerepel, azok egy verembe kerülnek, és Last-In, First-Out (LIFO) sorrendben hajtódnak végre – tehát az utoljára regisztrált `defer` fut le legelőször.
- **Fő felhasználási területe:** Erőforrások (fájlok, hálózati kapcsolatok, adatbázis-kezelők, mutexek) garantált felszabadítása még akkor is, ha a függvény idő előtt, hibával tér vissza.

```go
// 1. LIFO sorrend szemléltetése:
func lifoDemo() {
	defer fmt.Println("world")   // 3.-ként fut le
	defer fmt.Println("cruel")   // 2.-ként fut le
	defer fmt.Println("goodbye") // 1.-ként fut le
}

// 2. Valós felhasználás: fájl garantált lezárása hiba esetén is:
func writeToFile() error {
	file, err := os.Create("/tmp/foo.txt")
	if err != nil {
		return err
	}
	// Garantálja, hogy a fájl lezáródik, bárhol is térünk vissza a függvényből:
	defer file.Close()

	_, err = fmt.Fprintln(file, "hello")
	if err != nil {
		// Itt korán visszatérünk hibával, de a file.Close() automatikusan lefut!
		return err
	}
	return nil
}
```

## Paraméterátadás: érték szerint vs. referencia szerint

- **Érték szerinti átadás (Pass-by-value):** Alapértelmezés szerint Go-ban minden paraméter érték szerint adódik át, azaz a függvény egy másolatot kap az eredeti változóról. A másolaton végzett módosítások nem hatnak az eredeti változóra.
- **Referencia szerinti átadás (Pass-by-reference):** Ha azt szeretnénk, hogy a függvény módosítsa a hívó fél változóját, mutatót (`*T`) kell átadnunk (`&x`).
- **Referenciatípusok:** A szeletek (slice), asszociatív tömbök (map), függvények és csatornák (channel) belsőleg referenciatípusok, így mindig referencia szerint adódnak át (ha a függvény módosítja egy map vagy slice elemeit, az a hívónál is látszik).
- **Buktató (GOTCHA):** A rögzített hosszúságú tömbök (`[3]int`) érték szerint adódnak át (lemásolódnak a híváskor), ellentétben a dinamikus szeletekkel (`[]int`)!

```go
func zeroByValue(x int)     { x = 0 }  // Csak a másolatot nullázza
func zeroByReference(x *int) { *x = 0 } // Az eredeti memóriacímen lévő értéket nullázza

func updateMap(m map[string]int) {
	m["c"] = 2 // A map referenciatípus, az eredeti map is módosul
}

func main() {
	x := 5
	zeroByValue(x)
	fmt.Println(x) // 5

	zeroByReference(&x)
	fmt.Println(x) // 0

	m := map[string]int{"a": 0, "b": 1}
	updateMap(m)
	fmt.Println(m) // map[a:0 b:1 c:2]
}
```

## Variadikus függvények (Variadic functions)

- **Fogalom:** Olyan függvény, amely nulla vagy tetszőleges számú záró paraméterrel meghívható (ilyen például a `fmt.Printf(format string, a ...any)`).
- **Működése:** A típus elé írt ellipszis (`...T`) jelzi, hogy a függvény tetszőleges számú `T` típusú argumentumot fogad, amelyek a függvényen belül egy `[]T` szeletként érhetők el.
- **Szelet átadása:** Ha már van egy kész szeletünk, a `szelet...` szintaxissal „kicsomagolva” (flatten) átadhatjuk a variadikus függvénynek.

```go
func product(factors ...int) int {
	p := 1
	for _, n := range factors { // factors itt egy []int szelet
		p *= n
	}
	return p
}

func main() {
	fmt.Println(product(2, 2, 2)) // 8
	m := []int{3, 3, 3}
	fmt.Println(product(m...))    // 27 (szelet kicsomagolása)
}
```

## Függvények mint elsőrendű értékek, Callbackek és Lezárások (Closures)

- **First-class values:** Go-ban a függvények teljes értékű típusok: van típusuk (pl. `func(int, int) int`), van kezdőértékük (`nil` – egy `nil` függvény meghívása futásidejű panic-et okoz), változóba menthetők, paraméterként átadhatók és visszatérési értékként visszaadhatók.
- **Névtelen függvények és lezárások (Closures):** Egy függvényen belül definiált névtelen függvény hozzáfér a külső (szülő) függvény lokális változóihoz, és megőrzi ezeket a változókat azután is, hogy a szülő függvény már visszatért. Minden egyes hívás saját, független állapotot (state) hoz létre.

```go
// 1. Függvénytípus és callback:
type MyCallbackType = func(int, int) int

func sum(x, y int) int  { return x + y }
func prod(x, y int) int { return x * y }

func reportResult(callback MyCallbackType) {
	fmt.Println("Result:", callback(3, 4))
}

// 2. Closure (állapotmegőrző névtelen függvény):
func incrementer() func() int {
	i := 0 // Ezt a változót zárja be a belső függvény
	return func() int {
		i++
		return i
	}
}

func main() {
	reportResult(sum)  // Result: 7
	reportResult(prod) // Result: 12

	inc1 := incrementer()
	fmt.Println(inc1()) // 1
	fmt.Println(inc1()) // 2

	inc2 := incrementer() // Új, független állapotot kap!
	fmt.Println(inc2())   // 1
}
```

# 2. Struktúrák, metódusok és interfészek (Structs, Methods, and Interfaces)

## Struktúrák (struct)

- **Fogalom:** Elnevezett és típusos mezők (adattagok) gyűjteménye (`type <név> struct { ... }`). Az objektumorientált nyelvek osztályainak adatoldali megfelelője, de öröklődés nélkül.
- **Kezdőérték:** Minden mező felveszi a saját típusának zero value-ját (pl. `Vertex{}` esetén `{0 0}`).
- **Mutatók automatikus feloldása:** Ha egy struktúrára mutató pointerünk van (`v := &Vertex{1, 3}`), nem kell a nehézkes `(*v).X` írásmódot használnunk; a Go automatikusan feloldja a pont operátorral: `v.X`.
- **Rekurzív struktúrák:** Egy struktúra tartalmazhat önmagára mutató pointert vagy pointerek szeletét (pl. fa adatszerkezeteknél vagy HTML DOM csomópontoknál).

```go
type Vertex struct {
	X, Y float64
}

// Rekurzív struktúra példa (HTML DOM csomópont):
type node struct {
	tag, text  string
	attributes map[string]string
	children   []*node // Mutatók szelete ugyanilyen típusú csomópontokra
}

func main() {
	v1 := Vertex{1.0, 2.0}       // Sorrend szerinti inicializálás
	v2 := Vertex{Y: 2.5}         // Mezőnév szerinti (X automatikusan 0 lesz)
	vp := &Vertex{X: 1, Y: 3}    // Pointer struktúrára
	vp.X = 10                    // Automatikus dereferálás!
}
```

## Struktúrák másolása: Sekély vs. Mély másolás (Shallow vs. Deep Copy)

**Buktató (GOTCHA):** Amikor egy struktúrát értékül adsz egy másik változónak (`img2 := img`), a Go **sekély másolást** (shallow copy) végez. Ha a struktúra tartalmaz referenciatípusokat (map, slice, pointer), akkor csak ezek leírója/mutatója másolódik le, a mögöttes adatszerkezet közös marad!

**Mély másolás (DeepCopy):** Go-ban nincsenek copy-konstruktorok. Nekünk kell írnunk egy `DeepCopy` függvényt/metódust, amely rekurzívan újrafoglalja a belső mapeket és szeleteket. (Figyelem: a beépített `copy()` is csak sekély másolást végez pointerek szeletén!)

```go
func DeepCopy(n *node) *node {
	if n == nil {
		return nil
	}
	n2 := *n // Alap mezők (tag, text) sekély másolása

	// Map mély másolása:
	n2.attributes = make(map[string]string)
	for k, v := range n.attributes {
		n2.attributes[k] = v
	}

	// Gyerekek szeletének rekurzív mély másolása:
	n2.children = make([]*node, len(n.children))
	for i := range n.children {
		n2.children[i] = DeepCopy(n.children[i])
	}
	return &n2
}
```

## Metódusok (Methods)

A metódus egy adott típushoz csatolt függvény. Szintaxisa megegyezik a függvényével, de a `func` kulcsszó és a metódus neve között szerepel egy **fogadó argumentum (receiver)**, amely az OOP nyelvek `this` vagy `self` kulcsszavának felel meg (csak itt mi nevezzük el).

| Fogadó típusa | Szintaxis | Működés és mikor használjuk? |
|---|---|---|
| **Érték-fogadó** (Value receiver) | `func (v Vertex) Abs() float64` | A metódus a struktúra másolatát kapja meg. Nem tudja módosítani az eredeti példány mezőit. Kis méretű, nem módosítandó típusokhoz ideális. |
| **Mutató-fogadó** (Pointer receiver) | `func (v *Vertex) Scale(f float64)` | Elkerüli a struktúra másolását, és képes módosítani az eredeti példány állapotát. |

> **Ökölszabály:** Egy adott típus összes metódusánál válasszunk ki egy fogadótípust (vagy mind érték, vagy mind mutató), és használjuk azt következetesen!

## Interfészek (Interfaces) és Típusállítás (Type Assertion)

- **Fogalom:** Metódusszignatúrák halmaza, amely egy viselkedési szerződést (contract) ír le.
- **Implicit megvalósítás (Static duck typing):** Go-ban nincs `implements` kulcsszó. Ha egy típus megvalósítja az interfészben előírt összes metódust, akkor automatikusan teljesíti az interfészt („Ha úgy jár, mint egy kacsa, és úgy hápog, mint egy kacsa, akkor az egy kacsa”).
- **Típusállítás (Type assertion):** Egy interfész típusú változóból a `x.(T)` kifejezéssel nyerhetjük ki a mögötte rejlő konkrét típust. Mindig a kétváltozós („comma ok”) formát érdemes használni, mert ha a típus nem egyezik, nem omlik össze a program (`panic`), csak az `ok` értéke lesz `false`.
- **Az üres interfész (`any` / `interface{}`):** A Go 1.18 óta az `any` az üres interfész (`interface{}`) aliasa. Mivel nulla metódust ír elő, minden típus megvalósítja, így tetszőleges érték tárolására alkalmas.

```go
type Shape interface {
	Area() float64
}

type Circle struct{ Radius float64 }
func (c Circle) Area() float64 { return math.Pi * c.Radius * c.Radius }

type Rectangle struct{ Width, Height float64 }
func (r Rectangle) Area() float64 { return r.Width * r.Height }

// Polimorf függvény: bármilyen Shape-et elfogad
func PrintArea(s Shape) {
	fmt.Printf("%T területe: %0.2f\n", s, s.Area())
}

func main() {
	var s Shape = Circle{Radius: 5}
	PrintArea(s)

	// Biztonságos típusállítás (Type assertion):
	if c, ok := s.(Circle); ok {
		fmt.Println("Ez egy kör, sugara:", c.Radius)
	}

	// Üres interfész (any):
	var anything any = "bármilyen szöveg"
	str, ok := anything.(string) // str == "bármilyen szöveg", ok == true
	_ = str
}
```

# 3. Kompozíció és előléptetés (Composition & Promotion)

Go-ban nincs osztályalapú öröklődés; helyette **kompozíciót (beágyazást)** használunk meglévő típusok funkcionalitásának kombinálására.

## 1. Interfész-beágyazás (Interface embedding)

Több kisebb interfészt összevonhatunk egy összetett interfészbe. **Fontos szabály:** Interfészbe kizárólag másik interfészt lehet beágyazni!

```go
// A standard könyvtár io csomagjának felépítése:
type Reader interface {
	Read(p []byte) (n int, err error)
}

type Writer interface {
	Write(p []byte) (n int, err error)
}

// Összetett szerződés:
type ReadWriter interface {
	Reader
	Writer
}
```

## 2. Struktúra-beágyazás (Struct embedding) és Előléptetés (Promotion)

- **Beágyazás:** Ha egy struktúrán belül megadunk egy másik típust (vagy típusra mutató pointert) mezőnév nélkül, akkor beágyazzuk azt. (Nagyobb struktúráknál a pointeres beágyazás hatékonyabb, mert elkerüli a másolást.)
- **Előléptetés (Promotion):** A beágyazott típus minden exportált (nagybetűs) mezője és metódusa **előléptetődik** a külső struktúrára, így közvetlenül meghívható rajta, mintha a sajátja lenne! Emellett a beágyazott struktúra továbbra is elérhető a típusnevével mint mezőnévvel (pl. `rw.Reader`).
- **Mentális modell:** Gondolj az interfészre úgy, mint egy szerződésre (előírt viselkedésre), a struktúrára pedig úgy, mint a szerződés implementációjára (a hozzá csatolt metódusokon keresztül).

```go
// Példa a standard könyvtárból (bufio.ReadWriter):
type ReadWriter struct {
	*Reader // Beágyazott *bufio.Reader
	*Writer // Beágyazott *bufio.Writer
}

// Használat:
// rw := &bufio.ReadWriter{Reader: &bufio.Reader{}, Writer: &bufio.Writer{}}
// rw.Read(bytes) // Közvetlenül hívható a Promotion miatt!
```

# 4. Esettanulmány: Bérszámfejtő rendszer és Godoc (Case Study)

Az előadás egy alkalmazotti bérszámfejtő rendszeren mutatja be, hogyan érdemes refaktorálni egy programot kompozíció és interfészek segítségével:

- **Naiv megoldás:** Külön `Permanent` és `Contractor` struktúrák, külön `permSalary` és `contSalary` függvényekkel – így nem lehet egyetlen közös listában kezelni őket.
- **Interfész bevezetése:** Definiálunk egy `Employee` interfészt (`Salary() int`), így a `[]Employee` szeletben vegyesen tárolhatók az állandó alkalmazottak és az alvállalkozók.
- **Teljes általánosítás kompozícióval:** Mivel egy interfészen keresztül nem érhetjük el közvetlenül a struktúrák mezőit (pl. `e.name` fordítási hiba!), különválasztjuk a névvel rendelkezést (`Person` struktúra + `Named` interfész) a foglalkoztatási formától (`Employed` interfész), majd beágyazzuk a `Person`-t a `Permanent` és `Contractor` típusokba.

```go
package main

import "fmt"

// Named egy névvel rendelkező entitás szerződése.
type Named interface {
	Name() string
}

// Employed egy foglalkoztatott entitás szerződése.
type Employed interface {
	EmploymentType() string
	Salary() int
}

// Employee egyesíti a Named és Employed interfészeket.
type Employee interface {
	Named
	Employed
}

// Person tárolja a személyes adatokat és megvalósítja a Named interfészt.
type Person struct {
	name string
}

// Name visszaadja a személy nevét.
func (p Person) Name() string {
	return p.name
}

// Permanent beágyazza a Person típust (Promotion révén megkapja a Name() metódust!).
type Permanent struct {
	Person
	base, bonus int
}

func (p Permanent) Salary() int            { return p.base + p.bonus }
func (p Permanent) EmploymentType() string { return "permanent" }

// Contractor szintén beágyazza a Person típust.
type Contractor struct {
	Person
	fixPay int
}

func (c Contractor) Salary() int            { return c.fixPay }
func (c Contractor) EmploymentType() string { return "contractor" }

// totalSalary kiszámítja az összes alkalmazott összbérét.
func totalSalary(employees []Employee) int {
	total := 0
	for _, e := range employees {
		total += e.Salary()
	}
	return total
}

// reportEmployee tabulátorral tagolt jelentést ír ki egy alkalmazottról.
func reportEmployee(e Employee) {
	fmt.Printf("Name: %s\tEmployment: %s\tSalary: %d\n",
		e.Name(), e.EmploymentType(), e.Salary())
}
```

## Godoc dokumentáció és a go parancssori eszközök

**Godoc szabály:** Minden deklaráció fölé teljes angol mondatból álló kommentet kell írni, amely pontosan a deklarált azonosító nevével kezdődik (pl. `// Person stores...`). A Go ebből automatikusan HTML dokumentációt generál, és a linterek megkövetelik a használatát.

**Alapvető go parancsok:**

- `go run *.go`: Lefordítja és azonnal futtatja a programot.
- `go build`: Lefordítja a programot futtatható binárissá.
- `go test`: Lefuttatja a csomag egységtesztjeit.

# 5. Tesztelés Go-ban (Testing)

A Go beépített keretrendszert kínál az egységteszteléshez, külső könyvtár telepítése nélkül is:

- **Fájlnév:** A tesztfájlok nevének kötelezően `_test.go`-ra kell végződniük (pl. `employee_test.go`). Ezeket a fájlokat a normál `go build` figyelmen kívül hagyja.
- **Függvényszignatúra:** Minden tesztfüggvénynek `func TestXxx(t *testing.T)` alakúnak kell lennie, ahol az `Xxx` nagybetűvel kezdődik (pl. `TestTotalSalary`).
- **Hibajelzés:** A `*testing.T` segédobjektum `t.Error(...)` vagy `t.Errorf(...)` metódusával jelezzük, ha a teszt elbukott.
- **Futtatás:** `go test -v` (a `-v` kapcsoló részletes, tesztenkénti kimenetet ad). Összetettebb ellenőrzésekhez használhatók külső könyvtárak is (pl. `testify/assert` vagy `Ginkgo`).

```go
// employee_test.go
package main

import "testing"

func TestTotalSalary(t *testing.T) {
	emp1 := Permanent{Person: Person{name: "a"}, base: 5000, bonus: 1000}
	emp2 := Permanent{Person: Person{name: "b"}, base: 2500, bonus: 2000}
	emp3 := Contractor{Person: Person{name: "c"}, fixPay: 4000}

	total := totalSalary([]Employee{emp1, emp2, emp3})
	if total != 14500 {
		t.Errorf("totalSalary: expected 14500, got %d", total)
	}
}
```

# 6. Összegző tervezési alapelvek (Conclusions)

- **Erőforrás-kezelés:** Mindig használd a `defer` kulcsszót, hogy a megnyitott fájlok, hálózati kapcsolatok és lockok garantáltan felszabaduljanak.
- **Lezárások (Closures):** Kiválóak callbackekhez, de mindig figyelj arra, mely külső változókon osztozik a lezárás és a hívó fél.
- **Érték vs. Referencia:** Tudatosan válassz az érték szerinti (biztonságos, nem módosítja az eredetit, de másolással jár) és a mutató szerinti átadás között; ne feledd, hogy a `slice`, `map`, `func` és `channel` mindig referencia szerint adódik át.
- **Kompozíció öröklődés helyett:** Az objektumorientált osztályok szerepét Go-ban az interfész (szerződés) + struktúra (adat) + metódusok (viselkedés) hármasa veszi át, beágyazással kombinálva.
